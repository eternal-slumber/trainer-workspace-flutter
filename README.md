# TrainerWorkspace

Мобильное рабочее пространство фитнес-тренера на Flutter для Android и iOS.

## Запуск

```sh
flutter pub get
flutter run
```

По умолчанию включён **деморежим**. На приветствии нажмите «Войти», затем
«Открыть демо». Пароль не требуется; постоянно видна пометка
«Демонстрационные данные». Главное меню содержит подключение, сведения о
приложении и выход. В «О приложении» сохранено учебное `Hello, Android!`.
Существующая форма регистрации остаётся учебной: аккаунт на сервере не создаёт.

## Подключение к серверу

На приветствии, входе или в главном меню откройте «Подключение», выключите
«Демонстрационный режим» и укажите полный базовый URL:

```text
https://your-server.example/api/mobile/v1/
```

Завершающий `/` обязателен. Логин, пароль, query-параметры и токен в URL
запрещены. «Проверить подключение» вызывает публичный GET `health`; HTML-страница
с HTTP 200 не считается успешной проверкой. Настройка применяется кнопкой
«Сохранить подключение». Изменение сервера или режима очищает текущий сеанс.

Для настроек запуска можно создать локальный файл:

```sh
cp config/local.example.json config/local.json
```

В нём доступны только несекретные параметры, например:

```json
{
  "APP_MODE": "server",
  "API_BASE_URL": "https://your-server.example/api/mobile/v1/"
}
```

```sh
flutter run --dart-define-from-file=config/local.json
```

`APP_MODE`: `demo` или `server`. `config/local.json` исключён из Git.
Не помещайте пароли и токены в dart-defines: параметры сборки входят в приложение.
Настройки, изменённые на экране, действуют только до завершения процесса;
следующий запуск использует параметры сборки.

Для локального API с Android Emulator в **debug** можно использовать
`http://10.0.2.2:8000/api/mobile/v1/`. В debug также разрешены loopback-адреса
`localhost`, `127.0.0.1`, `::1`; произвольный HTTP-адрес запрещён. Для устройства
и release используйте доступный HTTPS-сервер с действительным сертификатом.
Проверка сертификатов не отключается.

## Авторизация и API

На Laravel-сервере должны быть реализованы следующие JSON-маршруты.
Их наличие на настоящем сервере пока не подтверждено:

| Метод | Маршрут | Назначение |
|---|---|---|
| GET | `health` | `data.status=ok`, `data.api_version=1` |
| POST | `auth/token` | email, password, device_name → Bearer-токен |
| GET | `me` | Подтверждённый профиль и настройки рабочего дня |
| DELETE | `auth/token` | Отзыв текущего токена, HTTP 204 |

Главное меню открывается только после успешных token **и** me. Токен хранится
**только в памяти процесса**; после завершения процесса нужен повторный вход.
Пароль не сохраняется и очищается с формы после попытки. Сетевые ошибки не
переключают серверный режим в демо. Повторный вход блокируется на время запроса.
Открытые экраны удаляются из стека при выходе, смене подключения и потере сеанса.
Если сервер недоступен при выходе, локальный сеанс очищается, а приложение
предупреждает, что серверный токен не удалось отозвать.

## Проверки

```sh
dart format --output=none --set-exit-if-changed lib test
dart analyze lib test
flutter test --no-pub
flutter build apk --debug --no-pub
```

APK: `build/app/outputs/flutter-apk/app-debug.apk`. Код не требует новых пакетов:
HTTP и JSON реализованы средствами Dart, состояние — ChangeNotifier и
InheritedNotifier, навигация — стандартным Navigator.

Тесты проверяют HTTP-контракт на локальном HttpServer, ошибки, отмену старого
входа, деморежим, очистку навигации, формы, поворот, доступность и большой шрифт.
Настоящий Laravel API и физическое устройство требуют отдельной проверки.
